# PySynoptic v0.2.0

## What's new

### Static Insights

PySynoptic can now explain the statically observable role of Python modules,
classes, functions, and methods. Each Insight may include:

- role;
- purpose and its provenance;
- qualitative confidence;
- responsibilities;
- inputs and outputs;
- side effects;
- callers and callees;
- supporting static evidence.

Insights complements the existing Architecture, Calls, and Flow views with a
concise answer to “What is this code element for?” before exposing the signals
behind that answer.

### Conservative by design

Confidence describes evidence quality, not probability:

- **HIGH** — multiple converging static signals;
- **MEDIUM** — useful static evidence with limitations;
- **UNKNOWN** — insufficient evidence for a reliable role.

PySynoptic prefers Unknown over an unsupported but convincing inference. Its
rules are deterministic and local: no AI or external service is required, no
analyzed source is transmitted, and analyzed code is never imported or
executed. Author-declared docstrings remain distinguishable from inferred
purposes.

### Navigation

Callable selection now stays synchronized across **Tree ↔ Calls ↔ Flow ↔
Insights**. Select a function or method from any of those views, inspect its
Insight, and move directly to its call neighborhood or control flow.
